# Chaplin — Movie Streaming Backend

Учебный pet-проект: backend для стримингового сервиса, демонстрирующий работу с P2P-протоколом (BitTorrent/WebTorrent), потоковой передачей видео через HTTP Range-запросы и интеграцией с внешним API (TMDB).

> Цель проекта — отработка инженерных задач: потоковая передача больших файлов по кускам (chunked streaming), работа с P2P-протоколами на Node.js, HTTP Range-запросы для перемотки видео, интеграция с внешними REST API.

## Стек

- **Node.js + TypeScript** (ESM-модули)
- **Express 5** — REST API
- **MongoDB + Mongoose** — хранилище метаданных фильмов
- **WebTorrent** — P2P-стриминг видео
- **TMDB API** — источник метаданных о фильмах (постеры, описания, актёры, трейлеры)
- **Cheerio + Axios** — парсинг торрент-раздач

## Как это работает

1. **Поиск фильма** — фронтенд ищет фильм по названию через TMDB API (`/movies/imdb-search`), получает список с постерами и рейтингом.
2. **Детали фильма** — по выбору пользователя подгружаются полные данные: описание, актёры, трейлер, производственные компании (`/movies/imdb/:id`).
3. **Поиск раздачи** — по названию и году бэкенд парсит HTML-страницу поиска на rutor.info через Cheerio, извлекает magnet-ссылки и фильтрует совпадения по точному названию/году (`/movies/search`).
4. **Стриминг** — magnet-ссылка передаётся в WebTorrent-клиент, из раздачи выбирается лучший видеофайл (`/stream/add/:magnet`). Дальше видео отдаётся клиенту потоково: сервер читает из торрента ровно тот диапазон байт, который запрашивает браузер через заголовок `Range`, и передаёт его напрямую в HTTP-ответ (`/stream/:magnet/:fileName`) — без промежуточного сохранения файла на диск.

## Установка и запуск

### 1. Поднять MongoDB через Docker

```bash
docker-compose up -d
```

### 2. Переменные окружения

Скопируй `.env.example` в `.env` и заполни:

```bash
cp .env.example .env
```

```
MONGO_URL=mongodb://localhost:27017/enjoyFilm
IMDB_API_KEY=<твой TMDB API key>
PORT=5000
```

> API-ключ получить бесплатно на [themoviedb.org](https://www.themoviedb.org/settings/api) — несмотря на название переменной (`IMDB_API_KEY`), используется именно TMDB API.

### 3. Установка зависимостей и запуск

```bash
npm install
npm run dev      # разработка (nodemon + tsx)
npm run build    # сборка в dist/
npm start        # запуск собранной версии
```

Сервер поднимется на `http://localhost:5000`.

## Основные эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| GET | `/health` | проверка доступности сервера |
| GET | `/movies/imdb-search?searchTerm=` | поиск фильмов через TMDB |
| GET | `/movies/imdb/:id` | детали фильма (актёры, трейлер, жанры) |
| GET | `/movies/search?searchTerm=&title=&originalTitle=&year=` | поиск раздачи на rutor.info с фильтрацией |
| GET | `/movies` | список сохранённых в своей БД фильмов |
| POST | `/movies` | сохранить фильм в MongoDB |
| GET | `/stream/add/:magnet` | инициализация торрента, список видеофайлов |
| GET | `/stream/:magnet/:fileName` | стриминг видео (с поддержкой Range) |
| GET | `/stream/stats` | текущий прогресс загрузки торрента |

## Важные технические детали

- **Стриминг без сохранения на диск** — видео передаётся напрямую из P2P-потока в HTTP-ответ через `createReadStream`, что позволяет начинать воспроизведение ещё до полной загрузки файла.
- **Умный выбор раздачи** — при поиске сортировка учитывает разрешение (оптимум — 1080p, а не максимально возможное), избегает Remux-раздач (слишком большой размер) и UHD/4K (избыточно для стриминга).
- **Не транскодирует видео** — сервер отдаёт исходный поток "как есть". Совместимость со звуком/видео зависит от кодеков конкретной раздачи (браузеры нативно не декодируют некоторые аудиокодеки вроде AC3/DTS).

## Известные ограничения (для дальнейшего развития)

- Нет очистки WebTorrent-клиента от неиспользуемых раздач по тайм-ауту
- Нет транскодирования аудио/видео на лету (ffmpeg)
- Собственная MongoDB используется как опциональный каталог "избранных" фильмов, основной поиск идёт напрямую через TMDB
